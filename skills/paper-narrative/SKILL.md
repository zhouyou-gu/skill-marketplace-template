# Paper Narrative

A narrative records how the paragraphs of a paper develop its argument. The following rules govern its preparation and revision.

1. **Scope.** The author’s request determines the paper, the passages covered, and the intended reader. Use the requested destination. If none is specified, update the paper’s existing narrative under its current filename. If none exists, create `NARRATIVE.md` beside the manuscript or, when working from a brief, in the paper’s directory.

2. **Basis.** Use the manuscript to determine what the paper currently says. Use the author’s brief or revision instructions to identify intended changes. If a proposed claim goes beyond the available material, the entry must identify the claim as proposed and state what support it still requires.

3. **Form.** Unless the author specifies another form, a new outline must have one numbered entry for each existing or planned paragraph within scope, in manuscript order. Each entry must identify the paragraph and state the point it establishes or is intended to establish. The drafter may add one level of indented bullets for supporting points. Each bullet must belong to that paragraph. Omit bullets when the entry is sufficient on its own. The paper determines the section names and paragraph count. See the [example NARRATIVE.md](examples/NARRATIVE.md).

4. **Content.** Use the paper’s terms. State a definition where the argument first relies on it. For a material inference, identify the supporting evidence or reasoning and retain any qualification that affects the conclusion. Read consecutive entries together to check that the reader can follow the reasoning from one paragraph to the next.

5. **Revision.** Update the affected entries in place. Preserve the author’s format and wording outside the requested change. If a change affects another entry within scope, revise that entry for consistency. If the affected entry falls outside an express limit, identify it in the response. Edit the manuscript only when the author expressly requests manuscript edits.

6. **Delivery.** For a preview or review, return the proposed text or edits. For a file update, report the narrative’s path, the change made, and any unresolved point material to the argument. The [tool contract](tool.json) defines the marketplace response fields.

For a requested section plan, apply the same rules of scope and support at section level. For a reader’s walkthrough, explain the paper’s reasoning in language suited to that reader. The [revision examples](examples/narrative-excerpts.md) illustrate how to apply these rules.
